# RequiBot — チャット形式 用件定義ツール（設計書自動生成対応）

> チャット形式Q&Aで用件を整理し、**用件定義書PDF** と **設計書PDF** を自動生成・ダウンロードできるツール。

**Live:** https://kinjomiyuki.github.io/requibot/

## Tech Stack

| Area | Tech |
|---|---|
| UI | HTML / CSS / JavaScript(ビルド不要) |
| PDF 出力 | jsPDF, html2canvas |
| Icons | Font Awesome |
| Hosting | GitHub Pages |

## Getting Started

`index.html` をブラウザで開くだけで動きます。

---

## 🌟 実装済み機能

### ホーム画面
- モード選択（Webサイト用 / アプリ・システム用）
- ダークテーマのモダンなビジュアル

### チャット画面（共通）
- タイピングアニメーション付きチャットQ&A
- セクション別サイドバーナビ（進捗インジケーター）
- クイック選択チップ（サジェスト）
- Enter送信 / Shift+Enter改行
- セクション切り替えヘッダー表示
- モード別カラーテーマ（紫系 / 緑系）
- 完了時のサマリーカード＋PDFボタン表示
- **リセット機能**

### 📐 設計書自動生成機能（NEW）
用件定義の回答を解析し、設計書を自動生成します。

**Webサイト用 設計書（7セクション）**
| セクション | 内容 |
|---|---|
| プロジェクト概要 | 基本情報・KGI・背景 |
| ターゲット定義 | ペルソナ・ユーザー像 |
| サイトマップ / ページ構成 | ページ一覧テーブル・優先度・CTA |
| 機能仕様 | 機能要件一覧（MoSCoW優先度付き） |
| デザイン仕様 | デザイン方針・チェックリスト |
| 技術スペック | インフラ構成・非機能要件テーブル |
| WBS / 開発スケジュール | 標準WBSテーブル（6フェーズ） |

**アプリ / システム用 設計書（9セクション）**
| セクション | 内容 |
|---|---|
| プロジェクト概要 | 基本情報・課題・スコープ |
| ユーザー・権限設計 | ロール定義テーブル・RBAC方針 |
| 機能仕様 | Must/Should/Nice機能一覧（MoSCoW） |
| 画面一覧 | UI方針・主要画面テーブル（自動推定） |
| データモデル | エンティティ一覧・設計方針 |
| API設計方針 | エンドポイント一覧（自動推定）・外部API |
| 非機能要件 | 可用性・パフォーマンス・セキュリティ等 |
| 技術スタック | フロントエンド〜インフラ構成表 |
| WBS / 開発スケジュール | 標準WBSテーブル（7フェーズ） |

### 📄 用件定義書PDF出力
- 表紙ページ（タイトル・作成日・目次・回答統計）
- セクション別ページ（Q&A形式レイアウト）
- A4縦フォーマット

### 📝 Markdown出力
- 用件定義書・設計書ともにMarkdown形式でコピー可能

## 📁 ファイル構成

```
index.html          # メインページ
css/
  style.css         # 全スタイル
js/
  questions.js      # 質問データ定義
  pdf.js            # 用件定義書PDF生成・モーダル制御
  design.js         # 設計書自動生成エンジン（NEW）
  chat.js           # チャットエンジン
```

### Webサイト用（10セクション・35問）
| セクション | 主な質問 |
|---|---|
| ① 概要・背景 | サイト種別、現状、背景、ステークホルダー |
| ② 目的・KGI | 最優先目的、副次目的、数値目標、競合参考 |
| ③ ターゲット | ペルソナ、サブターゲット、デバイス、リテラシー |
| ④ ページ構成 | ページ一覧、優先ページ、CTA、更新頻度 |
| ⑤ コンテンツ | テキスト、ビジュアル、多言語、アクセシビリティ |
| ⑥ デザイン | トーン、参考サイト、ブランドアセット、アニメーション |
| ⑦ UX・機能 | フォーム、EC/決済、会員機能 |
| ⑧ 技術・環境 | CMS、ホスティング、解析、外部連携、セキュリティ |
| ⑨ SEO・集客・運用 | SEO優先度、集客チャネル、保守体制 |
| ⑩ スケジュール・予算 | デッドライン、予算、体制、フェーズ2構想 |

### アプリ / システム用（11セクション・40問）
| セクション | 主な質問 |
|---|---|
| ① 概要・背景 | アプリ種別、背景、現状運用、ステークホルダー |
| ② 目的・KGI | 最重要課題、KGI/KPI、スコープ定義 |
| ③ ユーザー・権限 | ロール、認証方式、権限管理、規模、オンボーディング |
| ④ 機能要件 | Must/Should/Nice機能、管理画面機能 |
| ⑤ UX / UI | プラットフォーム、デザインシステム、UX優先度 |
| ⑥ データ設計 | エンティティ、リレーション、データ量、移行、保存ポリシー |
| ⑦ 非機能要件 | 可用性、パフォーマンス、スケーラビリティ、DR、監視 |
| ⑧ 技術スタック | フロントエンド、バックエンド、DB、インフラ |
| ⑨ 外部連携・API | 外部API、自社API公開、既存社内システム連携 |
| ⑩ セキュリティ・法令 | 法規制対応、データ分類、セキュリティ対策 |
| ⑪ スケジュール・体制 | MVPリリース日、フルリリース日、予算、開発体制、保守運用 |

## 🔗 URI / エントリポイント

| URL | 内容 |
|---|---|
| `/` → `index.html` | トップページ（モード選択） |
| 内部遷移: Web選択 | Webサイト用チャット起動（35問） |
| 内部遷移: App選択 | アプリ/システム用チャット起動（40問） |
| 出力モーダル | PDF / Markdown タブ切り替えで出力 |
